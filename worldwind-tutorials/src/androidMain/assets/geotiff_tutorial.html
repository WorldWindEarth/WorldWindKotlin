Tiled GeoTIFF Tutorial

Demonstrates the two ways a local tiled GeoTIFF can be mounted on the globe: GeoTiffImageLayer for raster imagery and GeoTiffElevationCoverage for a digital elevation model. Both read the same file format, so this tutorial drapes a GeoTIFF orthophoto over terrain that also came out of a GeoTIFF.

Neither type loads the file into memory. A GeoTIFF stores its raster as a grid of independently compressed tiles, and (once gdaladdo or a COG conversion has run) a ladder of reduced-resolution overviews alongside it. Each tile the engine draws picks the overview closest to its own resolution and decodes only the blocks it lands on — so a multi-gigabyte orthophoto costs the same per frame as a small one.

Running it

By default the tutorial synthesises both files into a temp directory at startup: a 512 × 512 Int16 DEM and a 1024 × 1024 RGB shaded-relief image of the same synthetic massif, internally tiled, Deflate-compressed, with a half-scale overview on the image. Set GEOTIFF_IMAGE and/or GEOTIFF_DEM (environment variable or system property) to run against real data instead; the two are independent, so a real DEM can be paired with the synthetic relief as long as they overlap.

What is supported

  • Classic TIFF and BigTIFF, striped or tiled, with overview IFDs read as a resolution ladder.
  • Uncompressed, LZW, Deflate and PackBits blocks, with the horizontal and floating-point predictors.
  • 8/16/32/64-bit samples, signed, unsigned or IEEE float; grayscale, palette and RGB(A) imagery; single-band DEMs with GDAL_NODATA voids.
  • Geographic (EPSG:4326), Web Mercator, and transverse-Mercator coordinates — which covers every UTM zone.

JPEG-compressed and band-separated (planar) rasters are not decoded; those blocks render as holes rather than as noise. A projection outside the list above is reported in the log and the file is refused rather than placed wrongly.

GeoTiffFragment.kt
